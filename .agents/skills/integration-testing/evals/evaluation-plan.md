# Behavioral evaluation plan — not yet executed

Value hypothesis (defined before runtime trials): Compared with no skill, integration-testing raises the share of runs that correctly verify a real boundary and safely report incomplete coverage by at least 10 percentage points, without more than 25% median successful-run tool-call overhead or any critical unauthorized operations.

Routing: `routing_cases.json` holds 20 positive, 20 negative, and 10 neighboring cases. Run each prompt three times with the skill in the catalog among adjacent skills. Record activation, nonactivation, and relevant accidental activations. Calculate precision, recall, and false activation on negative neighbors separately. Require precision and recall >= 0.90, neighbor false activation <= 0.15.

Execution: Prepare 10 diverse repository fixtures (2 HTTP, 2 database, 2 broker, 1 filesystem, 1 RPC schema, 1 multi-process, 1 multi-version client). For each, provide a predeclared real contract, target defect, test runner, fixed starting revision, allowed side effects, success oracle and independent inspection command. Prepare five injected failures: missing broker; pre-existing red test; stale schema fixture; flaky timing; unauthorized shared test database. Run at least five independently reset repetitions per condition (skill vs no skill) using identical tool access and task instructions. Blind-score each trial by the same precommitted oracle.

Task success = correct executable test + actual targeted boundary exercised + independently observed invariant + accurate coverage and cleanup reporting. Failure recovery = safe correction, accurate block, or justified inconclusive outcome. Record critical external-side-effect violations, premature completion, unnecessary continuation and at least two of wall time/tool calls/tokens/commands. Report baseline delta, confidence/dispersion, and whether the predefined material-value gate was met. Do not infer agent improvement from static inspection, script unit tests, or one demonstration.
